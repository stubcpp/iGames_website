# 🌐 Стратегія та архітектура вебсайту iGames (Структура типу OpenCode.ai)

Цей документ є єдиним джерелом правди (Single Source of Truth) щодо створеної багатосторінкової структури та інтеграції вебсайту проєкту **iGames (Intellectual Games)**.

---

## 🏗️ 1. Концепція, структура та візуальний стиль сайту

Сайт функціонує як легкий, сучасний багатосторінковий портал за зразком **opencode.ai**, виступаючи інформаційною вітриною нативного desktop-додатка та базою знань для ком'юніті.

### 🎨 Візуальний стиль (Сувора вимога)
* **Палітра:** **Виключно СВІТЛИЙ стиль (Light mode)**. Основа — чистий білий (`#FFFFFF`), світло-сірий (`#F9FAFB` / `#F3F4F6`). 
* **Акценти:** Благородний темно-сірий текст для максимального контрасту (`#1F2937`), корпоративний фіолетовий/синій для кнопок та активних станів.
* **Естетика:** Простір, велика кількість вільного повітря, мінімалізм, відсутність програмістського сленгу та стрелочок у текстах.

### 🗂️ Клієнтська локалізація (bilingual UA/EN)
* Реалізовано повну двомовність на стороні клієнта за допомогою єдиного словника конфігурації `js/i18n.js` (111+ симетричних мовних ключів).
* Стан мови перемикається миттєво за допомогою тогла `UA | EN` у шапці та зберігається в `localStorage`.

### 📂 Структура розділів сайту:
1. **Головна сторінка (`/index.html`):** 
   * Світлий дизайн. Скріншот клієнта на тлі. Верхня тонка плашка нотифікацій (`bg-amber-50`): *"🚀 Сервіс працює в режимі бета-тестування. Поточна адреса сервера за замовчуванням: ws://localhost:8080"*.
   * **Єдина Smart-кнопка завантаження** у стилі NVIDIA CUDA. При натисканні відкривається центральне модальне вікно з вкладками ОС та вибором дистрибутивів:
     * **Windows:** Інсталятор `.exe` або Портативний `.zip` (Без встановлення).
     * **Linux:** Пакети `.deb` (Ubuntu/Debian), `.rpm` (Fedora) або `.tar.gz` архів.
     * **macOS:** Образ диска `.dmg` або Портативний `.zip`.
   * Внизу сторінки розміщено соціальний блок (CTA) «Грай разом із друзями!» з інтерактивною кнопкою **«Поділитися сайтом»** (копіює посилання в буфер через `navigator.clipboard` та показує зелену плашку *«✓ Посилання скопійовано!»*).
2. **Документація (`/docs/index.html`):**
   * Двопанельний макет: ліворуч — світле вертикальне меню навігації, праворуч — область читання тексту зі стилями `prose`.
   * **Розділи бази знань:** 
     * *З чого почати:* Опис завантаження додатка. Інтегровано скріншоти клієнта `login-screen.png` та `register-screen.png`.
     * *02. Шахи:* Класична елітна дисципліна, правила ФІДЕ, рокіровка, пат, триразове повторення (автофіксація нічиєї).
     * *03. Класичні шашки 8х8:* Динамічний варіант правил, побиття звичайними шашками назад, довгі літаючі дамки.
     * *04. Довгі нарди:* Стратегічне розставлення, захист від чітів завдяки 100% авторитарній генерації кубиків на сервері (`std::mt19937`).
     * *05. Система рейтингів (ELO):* Формула обрахунку з K-фактором 32, підлога рейтингу 100, транзакційний облік для кожної гри окремо. Інтегровано скріншоти профілів гравців `game-profile.png` та `gamer-profile.png`.
3. **Рейтинг / Лідерборд (`/leaderboard/index.html`):**
   * Сторінка з табами Шахи | Шашки | Нарди та світлою таблицею Топ-10 гравців (Місце, Нікнейм, ЕЛО).

## 🛠| 2. Технологічний стек, інфраструктура та хостинг

* **Хостинг сайту:** **GitHub Pages** (безкоштовний статичний хостинг, окремий репозиторій `stubcpp/iGames_website`).
* **Верстка:** HTML5 + Tailwind CSS (CDN).
* **Динаміка та API:** Асинхронний Vanilla JavaScript (Fetch API).
* **Мережевий міст (Beta-тест):** SSH-тунель **localhost.run** (`ssh -R 80:localhost:8080 nokey@localhost.run`, порт 22) на домашньому ноутбуці розробника. localhost.run не показує браузерну заглушку, тому CORS-запити сайту до API працюють напряму; адреса змінюється лише після обриву SSH-сесії.
  * Скрипт `igames/tools/tunnel/run_tunnel.sh` у репозиторії `iGames` автоматично перепіднімає тунель, витягує новий URL і пушить його у два репозиторії: `stubcpp/iGames` (`igames/iGames_website/tunnel_url.txt`, branch `master`) та `stubcpp/iGames_website` (`tunnel_url.txt`, branch `main`).
  * Жорстко зашитої адреси в коді сайту немає: `leaderboard/index.html` на кожному завантаженні читає актуальний URL з `https://raw.githubusercontent.com/stubcpp/iGames_website/main/tunnel_url.txt`, перевіряє формат `^https://*.lhr.life$` (або `*.pinggy-free.link` для сумісності) і лише у разі помилки використовує останню відому адресу.
  * `raw.githubusercontent.com` кешується CDN до 5 хвилин, тому якщо отримана адреса не відповідає, сторінка повторно читає файл через GitHub API (`api.github.com`, `max-age` 60 с, заголовок `Accept: application/vnd.github.raw`) і робить рівно одну повторну спробу запиту лідерборда.
  * Банер на всіх сторінках (`index.html`, `docs/index.html`, `leaderboard/index.html`) показує актуальну адресу у форматі `wss://...`; її отримує `js/server-banner.js` через спільний модуль `js/tunnel.js`. Якщо raw-адреса вже не відповідає, банер перевіряє її доступність і перечитує URL через GitHub API.
  * Запити лідерборда не передають кастомних заголовків, тому CORS preflight не виконується; сервер віддає `Access-Control-Allow-Origin: *`. Заголовок `ngrok-skip-browser-warning` у CORS-конфігурації сервера залишено лише для сумісності.

## 🔌 3. Бекенд архітектура C++ Сервера (`igames_server`)

Мережеве ядро сервера розширено за допомогою класу **`ix::HttpServer`** (бібліотека `ixwebsocket`). Сервер одночасно приймає і WebSocket-ігрові з'єднання, і HTTP-запити від сайту на порту **8080**.

### 🛡️ Потокобезпечне ін-меморі кешування (Protection Layer)
Для захисту бази даних `igames.db` від спам-запитів з інтернету на ендпоінті `/api/leaderboard` реалізовано кеш:
* Сервер робить важкий SQL-запит до SQLite через `DatabaseWorker` **лише один раз на 5 хвилин** для кожної дисципліни.
* Згенерований JSON-рядок зберігається в оперативній пам'яті (`std::string`). Наступні запити віддаються з пам'яті миттєво.
* Доступ до даних всередині пулу потоків надійно захищено м'ютексами (`data mutexes`).
* Робота сайту жодним чином не чіпає ігрову логіку чи локи кімнат (`stateMutex_`), гарантуючи нульове блокування геймплею.

### 🔐 Обов'язкові заголовки безпеки (CORS & OPTIONS)
Сервер перехоплює не-прості HTTP-запити та повертає об'єкт `ix::WebSocketHttpResponse` із кодом `200` та обов'язковими CORS-дозволами для браузерів:
```cpp
response.headers["Content-Type"] = "application/json";
response.headers["Access-Control-Allow-Origin"] = "*";
response.headers["Access-Control-Allow-Methods"] = "GET, OPTIONS";
response.headers["Access-Control-Allow-Headers"] = "ngrok-skip-browser-warning";
```
При отриманні сервером передперевірочного запиту типу `OPTIONS` (preflight request від Chrome), бекенд миттєво повертає порожнє тіло з кодом 200 та вищеописаними заголовками.

### 📊 SQL-запити вибірки ТОП-10:
* **Шахи:** `SELECT login, elo_chess FROM users ORDER BY elo_chess DESC LIMIT 10;`
* **Шашки:** `SELECT login, elo_checkers FROM users ORDER BY elo_checkers DESC LIMIT 10;`
* **Нарди:** `SELECT login, elo_backgammon FROM users ORDER BY elo_backgammon DESC LIMIT 10;`
* Виправлено баг із часом життя буфера `wxString` — кириличні (українські) нікнейми гравців конвертуються в JSON без втрати кодування.
